# Execution plan: Wizard Mode in the real RTS world (playable vertical slices A to G)

Task-by-task guide for the agent that implements `PLAN_WIZARD_SETTLEMENT_STORIES.md` ("the plan"), revised 14 October 2026 after the owner's review and approved with decisions R1 to R5. **Implementation happens on `feature/wizard-mode-implementation` in its own worktree, per `WIZARD_IMPLEMENTATION_HANDOFF.md`; this planning branch is not the implementation branch.** Milestones run in order A to G; each ends at an owner checkpoint, and the next milestone starts only after the owner approves. Progress is ticked in `docs/ledger/WIZARD_STORIES_PROGRESS.md`. When this document and the plan disagree, this document wins; when the code disagrees with either, trust the code and the tests, then fix the document.

Repository root on the Ubuntu laptop is the implementation worktree (`/home/joe/dmb_runs/wt_wizard_implementation`, a git worktree of `/home/joe/Projects/DuelMasterBattle`; the planning worktree `/home/joe/dmb_runs/wt_wizard_stories` is not used for implementation). Simulation package: `WizardRTSHybrid/wizard_rts/`; new package: `WizardRTSHybrid/wizard_rts/narrative/`; Godot project: `godot_project/` (Godot 4.5.1 at `~/godot451/`). Commands are run from the repository root unless stated.

Relative complexity (S small: under a day; M: one to three days; L: a week; XL: more) is given per milestone and per task so the owner can weigh the order. Each milestone ends in something the owner can launch.

## 0. Working rules (read every session)

1. **Branch.** Work on `feature/wizard-mode-implementation` only (created from the final pushed HEAD of `feature/wizard-settlement-stories`, handover section C). Never merge into `main`, `feature/neuroevolution-plan` or `feature/wizard-settlement-stories`; the owner reconciles the branches. Push after every committed task. Do not touch the neuroevolution branch, its worktree, `WizardRTSHybrid/neuro/`, `docs/EXECUTION_PLAN_NEUROEVOLUTION.md`, `docs/PLAN_HIERARCHICAL_NEUROEVOLUTION.md`, `docs/ledger/NEUROEVO_PROGRESS.md`, `sim_api.py`, `visibility.py`, `ai*.py`, `history.py`, the hash baselines or `test_neuro_*`. Do not design training gates or schedule baseline changes.
2. **Ledger.** Read `docs/ledger/WIZARD_STORIES_PROGRESS.md` and `git log --oneline -10` first. Tick a task only when its "Done when" holds and its verification commands pass; write the evidence (command and result, or an evidence path under `WizardRTSHybrid/docs/evidence/narrative/<milestone>/`) on the same line. End every session with the ledger updated, committed and pushed, even mid-task ("IN PROGRESS: what is left").
3. **Content is frozen (D33).** No new buildings, units, wares, items, liquids, resources or cards. Never run `scripts/import_*.py`. Templates, packs, casts, archetypes, names, opponents and config are data, not content; `freeze.check()` must stay empty.
4. **No change to `world.py`.** The narrative layer hangs off `story.story_quantum`, `story.entity_rows`, `story.snapshot` and `story.WIZARD_OPS`. The only shared-simulation files this programme changes are `workers.py` (the summon, task C.2) and `magic.py` (residents as fire targets, D.3); each is additive, inert without a wizard op, and proven so by `test_hash_baseline.py` and `test_determinism.py` after the change. Any other need for a core change is a finding for the owner, not an edit.
5. **Determinism.** Sorted iteration; no wall clock; narrative randomness from `random.Random(zlib.crc32(...))` seeded by `(world.seed, ids, epoch)`; `world.rng` never touched.
6. **Nothing new writes `world.events`.** Narrative events go to `world.narrative["log"]` and to `story.snapshot()["narrative"]["events"]`. The two existing `story.py` appends stay as they are (they predate this programme).
7. **One world.** Every quest, character, dungeon and duel is bound to `HybridWorld`; no fixture implements a second rule; Godot owns no rules.
8. **Tests after every task.** Quick set: `python3 -m pytest WizardRTSHybrid/tests/test_story_slice.py WizardRTSHybrid/tests/test_quest_env.py WizardRTSHybrid/tests/test_duel_env.py WizardRTSHybrid/tests/test_ward_parity.py WizardRTSHybrid/tests/test_fire_magic.py WizardRTSHybrid/tests/test_narrative_*.py WizardRTSHybrid/tests/test_wizard_*.py WizardRTSHybrid/tests/test_content_freeze.py -q` (about 5 minutes). After any `workers.py` or `magic.py` touch add `test_hash_baseline.py test_determinism.py test_forestry.py test_logistics.py`. The full hybrid suite (`python3 -m pytest WizardRTSHybrid/tests -q --ignore=WizardRTSHybrid/tests/test_five_minutes.py`) at the end of every milestone.
9. **Headed proof.** A wizard-facing change counts as done only when a headed Godot script shows it (`WizardRTSHybrid/scripts/run_headed_suite.sh <name>`, each new script registered there) and a screenshot is stored under `WizardRTSHybrid/docs/evidence/narrative/<milestone>/`. The laptop screen is smaller than 1920x1080; shots are taken at the window size the suite uses. **Duel rule:** a headed test that counts toward a gameplay acceptance criterion plays the duel through the board's real input helpers (`ui_pointer_press_tray_spell`, `ui_action_select_locus`, `ui_action_pick_spell`, `ui_action_lock_ward`, `ui_action_cast`, `ui_advance_time`; `ui_set_fast_cast` may shorten the cast windows) and reads the result from `ui_get_result_text` and the Python lease; `ui_debug_finish_duel` is allowed only in interface smoke tests (B.3) and never satisfies B.4, C.4 or G.5.
10. **Commits.** One task per commit when practical, message `stories(<task id>): <what>` plus the attribution line the harness requires. Never `git add -A`; never commit `external/`, `runtime/`, saves, `~/dmb_runs`, or `docs/release_notes.md`.
11. **Stop points.** Stop and report to the owner at the end of every milestone (the ledger says OWNER CHECKPOINT) with the headed demonstration's screenshots and the measured numbers.
12. **Honesty.** Report measured numbers and test counts; a story that cannot be cast in a real world is a finding, not a failure to hide.
