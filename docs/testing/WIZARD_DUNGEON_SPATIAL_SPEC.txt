DUELMASTERBATTLE — WIZARD DUNGEON SPATIAL TEST SPEC

Purpose
-------
This file is the authoritative spatial/content brief for the Dungeon World Test.
It defines how the five non-human wizard dungeons should fit inside node maps,
their standard size, required rooms, objects, labels, mechanisms, and the state
relationships between them.

STANDARD SIZE
-------------
Verify current PuzzleKit room dimensions first. Historical values:
- common room: about 13x11 tiles
- maximum room: about 15x13 tiles

For this test use:
- standard room envelope: 15x13 tiles
- five-room dungeon reservation: 53x32 tiles

Reference packing:

+---------------+----+---------------+----+---------------+
|    ROOM 1     |    |    ROOM 2     |    |    ROOM 3     |
|     15x13     |    |     15x13     |    |     15x13     |
+---------------+    +---------------+    +---------------+
                         |
                         |
+---------------+----+---------------+
|    ROOM 5     |    |    ROOM 4     |
|     15x13     |    |     15x13     |
+---------------+    +---------------+

Width = 15 + 4 + 15 + 4 + 15 = 53
Height = 13 + 6 + 13 = 32

The reservation must not overlap node exits, mandatory roads/tracks, player
arrival points, or critical settlement buildings. The player must be able to
walk from node exterior into all five rooms and back outside without loading a
separate dungeon scene.

STANDARD DEBUG LABELS
---------------------
DUNGEON:<dungeon_id>

WIZARD:<wizard_id>
ITEM:<item_id>
MECH:<mechanism_id>
GATE:<gate_id>

Labels must be toggleable.

COMMON REQUIREMENTS
-------------------
Every dungeon must have:
- an exterior approach inside the node
- five room envelopes
- physical walkable connectors
- no loading transition between node and dungeon
- a safe route back outside
- at least one real PuzzleKit interaction in the spatial prototype
- debug labels for rooms and critical entities
- a final wizard marker/actor in room 5
- recoverable/resettable required puzzle states
- enough adjacent walkable space to interact with objects

GW — THE ROOTBOUND SANCTUARY
----------------------------
Dungeon ID: dungeon.gw.rootbound_sanctuary
Wizard ID: wizard.gw.treefolk
Terrain concept: Forest/Woodland
Fantasy: RESTORE THE SYSTEM RATHER THAN BREAK IT.

Room 1 — ROOT GATE
Room ID: gw.root_gate
Required:
- SIGN:gw.seasons_carving
- MECH:gw.root_barrier
- GATE:gw.root_gate
Clue: a tree passes through four seasons and returns to life.
Must always permit retreat to exterior.

Room 2 — SEED SHRINE
Room ID: gw.seed_shrine
Required:
- ITEM:item.gw.sun_seed
- RECEPTOR:gw.seed_shrine
Clue: "What sleeps in winter is not dead."
Sun Seed must remain recoverable while required.

Room 3 — WITHERED CHANNEL
Room ID: gw.withered_channel
Required:
- MECH:gw.channel_weight
- MECH:gw.channel_plate
- MECH:gw.water_switch
- STATE:gw.water_restored
Correct state visibly restores water/life.

Room 4 — HEARTWOOD CHAMBER
Room ID: gw.heartwood_chamber
Required:
- ITEM:item.gw.sun_seed
- RECEPTOR:gw.growth_point
- STATE:gw.water_restored
- GATE:gw.living_gate
Rule: water_restored AND sun_seed installed -> living gate opens.

Room 5 — ELDER COURT
Room ID: gw.elder_court
Required:
- WIZARD:wizard.gw.treefolk
- safe exit/return route

Flow:
restore water -> install seed -> open living gate -> reach GW wizard

NODE SIZE COMPARISON
--------------------
The test must support:
- 65x49
- 73x55
- 81x61

For each profile show or record:
- node dimensions
- 53x32 dungeon reservation bounds
- remaining exterior area
- whether exits/roads/settlement geometry remain usable
- approximate traversal distance
- path from node exterior into dungeon and back

PUZZLEKIT REUSE
---------------
At least one embedded five-room sample must reuse real existing PuzzleKit mechanics.
Prefer representative mechanisms covering:
- ordered sequence/reveal
- NPC scripted interaction
- timed/moving mechanism
- environmental magic
- counterweight/drop
- throw/pressure plate/multi-solution

Verify current catalogue IDs on the branch before choosing exact puzzles.

ACCEPTANCE
----------
PASS requires:
1. Five rooms physically fit inside a node.
2. No dungeon scene/loading transition is used inside the test node.
3. Player can walk in and back out.
4. Node exits and critical settlement routes remain usable.
5. At least one embedded dungeon uses real PuzzleKit logic.
6. Required objects/mechanisms are clearly identifiable.
7. State changes are readable.
8. Debug labels can identify rooms and critical entities.
9. No required sequence can permanently softlock.
10. 65x49, 73x55 and 81x61 can be compared.
11. 450x800 and 720x1280 portrait remain usable.
12. Production dungeon behavior remains intact outside the fixture.

SCOPE LIMIT
-----------
This file describes dungeon SHAPE, SIZE, REQUIRED OBJECTS, LABELS and STATE
RELATIONSHIPS. It does not authorize:
- final dungeon art
- permanent production replacement of dungeon scene transitions
- final plot implementation
- permanent BG terrain assignment
- combat redesign
- PuzzleKit rewrite
- permanent global node-size choice
