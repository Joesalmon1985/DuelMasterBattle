# Duel Master Battle — Supervisor Router (`.hermes.md`)

The supervisor decides which specialist discipline applies and reviews worker output.
One worker at a time is the default. For mixed work, stage ownership — never assign one
generic worker to do everything. Delegated implementation uses the currently configured
implementation model unless there is a compelling technical reason to change it.

## Routing

| Work | → Role file (read first) |
|---|---|
| Narrative/story prose, scene construction, pacing, tone | → `docs/roles/narrative_director.md` |
| NPC dialogue, characterisation | → `docs/roles/character_dialogue_writer.md` |
| Puzzle conception, clueing, teaching, fail-forward design | → `docs/roles/puzzle_designer.md` |
| Signs, inscriptions, corpses, room dressing, item text, spatial storytelling | → `docs/roles/environmental_storyteller.md` |
| Story-state consistency, flags, repeat visits, save/load continuity | → `docs/roles/continuity_editor.md` |
| Puzzle graphics, visual state readability, placeholders | → `docs/roles/visual_puzzle_director.md` |
| Godot implementation (implements approved designs; owns no redesign) | → `docs/roles/godot_gameplay_engineer.md` |
| Rules/testing, test contracts, verification | → `docs/roles/rules_test_engineer.md` |
| Whole-feature evaluation, blind playtesting, repro-step findings | → `docs/roles/qa_playtest_critic.md` |

## Preferred sequences

Substantial puzzle work:
`puzzle_designer` → `visual_puzzle_director` → `godot_gameplay_engineer` →
`rules_test_engineer` → `qa_playtest_critic`

Substantial story work:
`narrative_director` (+ `character_dialogue_writer` where NPCs speak) →
`continuity_editor` → `godot_gameplay_engineer` → `qa_playtest_critic`

## Delegation rule

Every `delegate_task` for substantial work must: name the specialist role; tell the worker
which `docs/roles/...` file to read first; give a bounded goal, relevant file paths, and
explicit acceptance criteria; require inspecting existing work before modifying it; require
appropriate verification (tests, flow scripts, and/or inspected screenshots as the role demands).
Never send a vague instruction such as "improve the puzzles".

## Authority order

Current implementation + canonical docs (`docs/NARRATOR_VOICE.md`, `docs/FIRST_ADVENTURE.md`,
`docs/PRD.md`, puzzle/node-map txt files, `docs/DEATHTRAP_OVERHAUL_PLAN.md`,
`content/dd_canon.json`) override anything stale elsewhere. `docs/SECOND_ADVENTURE_PLAN.md`
is superseded (wound/ledger ideas only). `docs/RULES.md` and `docs/ENCOUNTER_DESIGN.md` are
empty stubs — do not cite them as authority. Old milestone labels (M4/M7/M10) and Godot 4.4.x
paths in legacy docs are obsolete; discover the installed Godot version at task time.

## Secrets

Never expose, copy, print, log, or alter API keys, credentials, `.env` values,
authentication files, or other secrets. Verification steps must not cat credential files.
